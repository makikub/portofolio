# Cursor / Codex / Claude 共通の記事種プロンプト

現在の個人開発・副業の作業から、本人が記事にしてよいと指定した範囲だけで実践ノートを整理する。

1. 対象の許可を確認する。会社・顧客資料、会話ログ、秘密値を探索しない。収集allowlistは公開許可そのものではない。
2. 読者が何を再現・判断できるかを一文で言えない活動はスキップする。単なる進捗、ツールの羅列、裏付けのない成功談を記事にしない。
3. テンプレートの9項目に、課題、AIの担当、人の判断、実施手順、検証した成果、失敗、再現条件、限界、学びを記入する。
4. 事実には直接確認した公開根拠を付ける。検討だけのことはplanned、解釈はinferenceに分ける。根拠の内容と主張の対応を読み直す。公開根拠がない成果は断言しない。
5. 元の非公開名、URL、ローカルパス、個人情報を一般化・削除する。顧客の説明がないと成立しない記事は止める。
6. 本人が公開可能として指定した抽象化済み内容に限りpublic_releaseをtrueにする。公開可否が不明ならfalseのまま別のローカル下書き領域に保存し、公開seed_dirへ入れない。
7. `dry-run`を実行し、previewを読み直す。形式検査合格だけで事実確認済みとは扱わない。本人のPRレビューを必須とする。

文体: 既存サイトの「判断と実践」を軸に、具体的で落ち着いた日本語を使う。AIが全て解決したように誇張しない。検証できた範囲とまだ試していないことを書く。成果がなくても再現可能な失敗の学びがあれば候補にできる。

振り返りの保存時は `docs/article-pipeline.md` のprivate envelope形式を使い、本人指定のdevice_id、source_tool、project_id、event_id、選択済みのprivate_refsを付ける。端末識別子や非公開参照をseed本文へ混ぜない。同じ実験を別端末で続ける場合はproject_id/event_idを共有する。MacBook Proや別サービスへ勝手に接続しない。履歴が見えない範囲を実施済みと書かない。
