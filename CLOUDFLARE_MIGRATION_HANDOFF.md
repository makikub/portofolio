# Cloudflare Pages Migration Handoff

## Goal

Migrate this Astro portfolio site from Firebase Hosting to Cloudflare Pages.

Target Cloudflare Pages project name:

```txt
masaki-portfolio
```

Expected temporary production URL:

```txt
https://masaki-portfolio.pages.dev
```

After Cloudflare Pages is verified, use Cloudflare-managed custom domain if needed.

## Current State

- Framework: Astro 4 + Tailwind CSS
- Current hosting: Firebase Hosting
- Current production URL: https://masaki-k-portofolio.web.app
- Build command: `npm run build`
- Build output directory: `dist`
- Firebase config: `firebase.json`
- Astro site URL is currently not production-ready:

```js
site: 'https://yourdomain.com'
```

## Cloudflare Pages Settings

Use these settings when creating the Cloudflare Pages project.

```txt
Project name: masaki-portfolio
Framework preset: Astro
Build command: npm run build
Build output directory: dist
Deploy branch: main
Node.js version: 20
```

Node.js 18 should also work, but use Node.js 20 unless there is a specific reason not to.

## Repository Changes To Make

### Required

Update `astro.config.mjs` after the Cloudflare Pages URL is available.

```js
site: 'https://masaki-portfolio.pages.dev'
```

This fixes OGP and Twitter Card URLs generated by Astro.

### Recommended

Update deployment documentation in `README.md` or a dedicated maintenance document.

The new deployment flow should say:

```bash
npm run build
```

Cloudflare Pages deploys automatically from GitHub after changes are pushed to the deploy branch.

For manual verification:

```bash
curl -I https://masaki-portfolio.pages.dev
```

Expected result:

```txt
HTTP/2 200
```

## Things To Keep During Migration

Keep these until the Cloudflare deployment has been verified in production.

- `firebase.json`
- Existing Firebase Hosting project
- Existing Firebase production URL

Reason: they provide a simple rollback path while Cloudflare Pages is being validated.

## Things To Delete After Verification

After Cloudflare Pages is confirmed working and the new URL/domain is accepted, remove Firebase-specific files and docs if they are no longer needed.

Candidates:

- `firebase.json`
- Firebase deploy instructions in `README.md`
- Firebase references in `SETUP_GUIDE.md`
- Firebase references in `CLAUDE.md`
- Firebase references in `要件定義書.md`, if the requirement document should reflect the new hosting decision

Before deleting documentation, check whether it is historical context or active operating guidance.

## Migration Procedure

1. Confirm the current app builds locally.

```bash
npm run build
```

2. Create a Cloudflare Pages project named `masaki-portfolio`.

3. Connect the GitHub repository.

4. Configure Cloudflare Pages.

```txt
Framework preset: Astro
Build command: npm run build
Build output directory: dist
Deploy branch: main
Node.js version: 20
```

5. Trigger the first Cloudflare Pages deploy.

6. Verify the deployed URL.

```bash
curl -I https://masaki-portfolio.pages.dev
```

Expected:

```txt
HTTP/2 200
```

7. Open the deployed page and check the main sections render.

- Header
- Hero
- Skills
- Featured Projects
- External Articles & Profiles
- Contact
- Footer

8. Update `astro.config.mjs`.

```js
site: 'https://masaki-portfolio.pages.dev'
```

9. Run build again.

```bash
npm run build
```

10. Commit and push the change.

11. Confirm Cloudflare Pages redeploys successfully.

12. Verify the HTML contains the Cloudflare Pages URL in OGP/Twitter metadata.

```bash
curl -L https://masaki-portfolio.pages.dev
```

Check for:

```html
https://masaki-portfolio.pages.dev/
```

13. Keep Firebase running for a short validation period.

14. After validation, remove Firebase-specific config and docs if no longer needed.

## Rollback

If Cloudflare Pages deployment fails or renders incorrectly, keep using:

```txt
https://masaki-k-portofolio.web.app
```

Do not delete Firebase config or Firebase Hosting until Cloudflare Pages is verified.

## Known Non-Migration Issues

These are existing issues and should not block the hosting migration unless the owner asks to address them.

- `Contact.astro` has a visual form only. It does not submit anywhere yet.
- `src/data/social.json` still contains `your.email@example.com`.
- `About.astro` exists but is not currently included in `src/pages/index.astro`.
- `AGENTS.md` is currently untracked in git.
